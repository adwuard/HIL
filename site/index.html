Every instrument speaks SCPI. Every vendor speaks it differently.

HIL is the layer that makes a bench behave like one coherent, safety-checked machine instead of a drawer of dialects.

safety by default

Each device profile carries a policy. The bench refuses to send a command the profile blocks, and enforces limits on the ones it allows, before anything reaches the hardware.

simulator first

Every procedure is plain YAML you can dry-run with --sim and validate statically with no instrument attached, so a bad plan fails on your laptop, not on your DUT.

one byte-pipe

TCP, serial, VISA/GPIB, PPK2, logic-analyzer and debug transports all resolve through a single addressing scheme and a single driver registry.

Eleven layers, one import.

From the socket up to the command line, each layer has a single job and a stable --json contract.

transport

Byte-pipes over TCP, serial and VISA/GPIB, with uniform connect/read/write semantics.

instrument

The device object: write, query, safe_execute and capture against whatever is addressed.

drivers

Pluggable implementations (scpi, ppk2, logic, debug) plus third-party entry points.

provision

On-demand setup of optional backends via declarative recipes: detect, fetch/build, verify.

registry

YAML device profiles: capabilities, command sets, connection examples and a safety policy.

addressing

One resolver for tcp://, serial://, visa://, ppk2://, logic://, debug:// or a registry slug.

telemetry

Channel sampling into summary stats and NDJSON, for soak tests and drift watches.

artifacts

Captures and logs spooled as versioned artifacts (.atkdl, NDJSON, CSV) you can re-decode later.

errors

The instrument SYST:ERR? queue drained and surfaced as structured facts, not silence.

bench

Procedures as data: YAML plans you can validate, simulate and run against real addresses.

cli

An agent-first CLI where every command emits stable --json with meaningful exit codes.

Built to be driven by an agent.

Structured output everywhere, a simulator for rehearsal, and an MCP server so your coding agent treats the bench as a set of tools with parseable results.

HIL MCP tools
ToolWhat it does
hil_doctorBench readiness: version, importable backends, device count, provisioning hints
hil_devices / hil_deviceSearch the registry / fetch one device's full profile (capabilities, commands, safety policy)
hil_probeConnectivity check: *IDN? + *OPC?, parsed identity
hil_execRun SCPI commands (a trailing ? queries); safety policy enforced; one structured result per command
hil_errorsDrain the instrument's SYST:ERR? queue
hil_captureSample a channel for N seconds → summary stats (mean/min/max/p95/rate), optional NDJSON dump
hil_debug_probeList attached debug probes (name/type/serial), no target needed
hil_debugFlash / erase / reset / halt / step / read / write / RTT / GDB against a debug:// target
hil_setupCheck or plan backend provisioning (dry-run by default; never silently installs system packages)

Every tool returns a JSON object with an ok flag: on failure ok:false plus an error message rather than a transport-level crash, so the model always gets parseable facts. The registry is also exposed as MCP resources at hil://devices.

Install it in three sentences.

Paste these to any coding agent (Claude Code, Cursor, Codex or Qoder) and it will do the rest. Each card shows the exact shell equivalent.

1 install

“Install the HIL hardware-in-the-loop harness from GitHub, including the MCP extra.”

pip install 'git+https://github.com/adwuard/HIL.git#egg=hil-harness[mcp]'

2 register

“Register HIL’s MCP server in my coding agent and confirm it’s reachable.”

hil mcp install

3 verify

“Run hil doctor to check bench readiness and provision my device backend, for example ppk2 or alientek-atk-logic.”

hil doctor && hil setup ppk2

Prefer the shell? pip install git+https://github.com/adwuard/HIL.git, then add extras as needed: .[serial], .[visa], .[atk], .[ppk2], .[mcp] or .[all]. Python 3.10+; the core needs only PyYAML.

Questions, answered plainly.

What is HIL?

HIL (hil-harness) is a Python hardware-in-the-loop testing harness for lab instruments. It drives SCPI instruments plus non-SCPI tools (power profilers, logic analyzers, on-chip flash/debug probes) through one Python API, one CLI and one MCP server, with a safety policy on every device profile.

Does it need real hardware to run?

No. HIL ships a simulator so procedures dry-run with hil bench run <plan>.yaml --sim before touching hardware. Real benches are addressed with tcp://, serial://, visa://, ppk2://, logic:// or debug:// URLs when you are ready.

Which instruments does it support?

The corpus covers 725 instruments from 7 vendors and roughly 294k SCPI commands. Eight hand-curated profiles load by default with safety policies, listed above, and the registry extends with your own YAML profiles.

How do I install it?

HIL is not on PyPI yet. Install from GitHub with pip install git+https://github.com/adwuard/HIL.git, or paste one of the three natural-language prompts above to your coding agent.

What does it cost, and what is the license?

Free and open source under MIT. The optional Nordic PPK2 backend wraps the GPLv2 ppk2-api library and is provisioned on demand, keeping the MIT core clean.

Does it work with my coding agent?

Yes. hil mcp install registers the MCP server with Claude Code, Codex, Cursor, Qoder, Windsurf and Cline. Every tool returns JSON with an ok flag, so agents always get parseable facts instead of crashes.
